# Guía de Capacitación — Upgrade La 79

FINAL-PRODUCT-01D · 1 de octubre de 2026 · Material para el propietario/instructor.

Este documento enseña **cómo capacitar**. El [Manual de Usuario](user-manual.md) conserva el detalle de campos; no lo reemplazamos ni lo reescribimos. Abre junto a esta guía el [guion de presentación](training-script.md), los [escenarios](training-scenarios.md) y la [checklist](training-checklist.md). Los tiempos son orientativos, no límites para presionar al aprendiz ni reglas del negocio.

## 1. Método: explicar, mostrar, hacer juntos, practicar, comprobar

1. **Explicar:** describe una situación del negocio y el resultado buscado, antes de nombrar botones.
2. **Mostrar:** realiza un ejemplo corto; señala sede, identidad, estado anterior y consecuencia del guardado.
3. **Hacer juntos:** el aprendiz maneja el navegador. Tú preguntas qué sigue antes de indicarlo.
4. **Practicar sin guía:** cambia el dato ficticio o utiliza otro registro de entrenamiento; guarda silencio mientras decide. No repitas una venta/pago/entrada sólo para practicar el mismo clic.
5. **Comprobar:** revisen el registro resultante, saldo/stock/estado y trazabilidad. Pide al aprendiz explicar qué cambió y qué no cambió.

No impartas toda la sesión como exposición. Alterna breves explicaciones con uso real. Haber visto al instructor no equivale a saber hacerlo. Un error corregido con ayuda sigue necesitando práctica independiente. Si el entorno no permite una acción, marca **No visto** o **Necesita refuerzo**, no “Aprendido”.

## 2. Preparación del instructor: antes de iniciar el reloj

- [ ] Entorno de entrenamiento identificado y aislado; no producción ni bases operativas. Esta fase sólo crea documentos: los ejercicios se ejecutarán durante una capacitación autorizada.
- [ ] Navegador actualizado, acceso local suministrado, ventanas disponibles para CRM y tienda; sin sesiones/capturas privadas expuestas.
- [ ] Cuenta individual correcta: Admin para gestión; Usuario vinculado a empleado para colaborador. No se comparten contraseñas ni se imprimen en material.
- [ ] Sede comprobada: Barranquilla (BAQ) y Bogotá (BOG) activas; colaborador activo en la sede prevista. No modificar sedes reales para una demostración.
- [ ] Permisos revisados con [Roles y permisos](roles-permissions.md). Consulta, crear, convertir, pagar y completar son acciones distintas. Crear acceso CRM no concede automáticamente todas.
- [ ] Prefijo único de sesión y datos ficticios de [preparación de escenarios](training-scenarios.md#preparacion); busca antes de crear.
- [ ] Categoría, listas de vehículos y servicio con categoría activa preparados. Compatibilidad confirmada; no rellenar años/modelos al azar.
- [ ] Tres fotografías propias de entrenamiento, sin datos privados, JPEG/PNG/WebP y máximo 5 MB cada una.
- [ ] Productos/variantes y stock suficientes en cada sede para los ejercicios. Anota los saldos iniciales, no sólo disponibilidad de red.
- [ ] Cliente y vehículo ficticios previstos; empleado con jornada y franjas libres para citas/tareas, ausencia en una franja separada.
- [ ] Caso ficticio de conciliación y estados públicos de pago disponibles para lectura/demostración, si corresponde. No generar cobros, devoluciones ni discrepancias reales.
- [ ] Para una prueba pública de pago: entorno de pruebas aprobado, sin fondos reales ni comunicaciones a clientes. Si no existe, detenerse antes de la pasarela y explicar con evidencia autorizada; no certificar pago ejecutado.
- [ ] Checklist abierta con nombre interno del aprendiz, perfil, fecha y competencias elegidas; no registrar credenciales.

Si falla una condición de seguridad, no continúes con escrituras. Puedes enseñar navegación/lectura y registrar lo pendiente. El dominio previsto upgradecolombia.com todavía no está desplegado: no lo presentes como entorno de entrenamiento activo.

## 3. Mapa y tiempos

**Conceptos → Catálogo → Inventario → Clientes → Cotizaciones → Ventas → Pagos → Operación → Control/Reportes.**

Primero aprendemos qué representan los datos; después creamos lo vendible y lo abastecemos. Cliente/vehículo permiten reutilizar información; la cotización se convierte sin repetirla. Dinero y terminación se enseñan por separado. Agenda/personal organizan ejecución, y los controles permiten revisar el resultado sin “arreglar” datos arbitrariamente.

| Itinerario | Duración | Distribución y alcance |
|---|---|---|
| Admin inicial | 90 min | Conceptos 5 + nueve lecciones 80 + cierre 5; orientación completa y ejercicios centrales, no todos los casos extremos |
| Admin avanzado/refuerzo | 45–60 min | Sólo competencias pendientes: variantes/listas, personal, incidencias y evaluación independiente; no repetir lo aprobado |
| Colaborador | 30 min | Conceptos 5 + cuatro lecciones 20 + cierre 5; únicamente espacio propio y permisos disponibles |
| Ecommerce/demostración | 20 min | Orientación pública 2 + tres lecciones 16 + cierre 2; no enseñar CRM al comprador |
| Repaso posterior | 10–15 min | Una operación independiente y revisión de errores recientes; ampliar únicamente si queda una competencia crítica pendiente |

En la sesión inicial hay módulos que se presentan con registros preparados. Las habilidades de crear/editar en ellos se verifican después si no caben en el tiempo. No comprimas una transferencia, cobro o confirmación para cumplir el reloj; pausa, marca refuerzo y acuerda la práctica pendiente.

## 4. Lección común: conceptos que bloquean el avance

### C0. Separar ficha, unidades, propuesta, operación y dinero

**Objetivo**

Comprender las siete separaciones antes de guardar una operación.

**Duración estimada**

5 minutos en Admin/colaborador. Ecommerce utiliza la introducción pública de dos minutos del guion.

**Qué debe saber antes**

Cuál es su cuenta, perfil y entorno de entrenamiento.

**QUÉ HACER**

Dibuja una ficha, dos sedes y una venta. Pregunta dónde se registran las unidades y el dinero. No pulses botones de guardado todavía.

**QUÉ DECIR**

“Crear un producto no crea inventario. El inventario pertenece a una sede. Cotizar es proponer, no vender ni reservar stock. La venta no es el pago, y pagar no termina la atención. Trasladar requiere despacho y recepción, no dos ajustes. Admin gestiona el negocio; el colaborador trabaja sobre su información autorizada.”

**QUÉ MOSTRAR**

Ficha del artículo, una posición BAQ y otra BOG, cotización, estado operativo y saldo de una venta ficticia. Enseña sólo las lecturas autorizadas al perfil; al colaborador explica catálogo/stock verbalmente, sin abrir módulos Admin.

**QUÉ DEBE HACER EL APRENDIZ**

Explicar con sus palabras las siete diferencias y resolver: “Hay dos unidades en BOG, ninguna en BAQ: ¿puedo vender desde BAQ como si estuvieran allí?”.

**RESULTADO ESPERADO**

No confunde Producto ≠ Stock, Cotización ≠ Venta, Venta ≠ Pago, Pago ≠ Finalización, stock por sede, Transferencia ≠ Ajuste y Admin ≠ Colaborador.

**ERRORES QUE DEBES EXPLICAR**

Salida manual duplicada por venta, entrada duplicada por transferencia y segunda orden por pago pendiente son errores, no soluciones.

**PREGUNTAS DE CONTROL**

1. ¿Publicar una foto agrega unidades?
2. ¿Una orden pagada puede seguir Confirmada?
3. ¿Qué falta para disponer en destino de unidades En tránsito?

**APROBADO SI**

Explica las siete separaciones sin ayuda y responde los tres casos. **NO CONTINÚES HASTA QUE EL APRENDIZ ENTIENDA ESTO.** Si no lo logra, detén las escrituras y refuerza [Manual §3](user-manual.md#conceptos).

## 5. Itinerario Admin: nueve lecciones

### A1. Orientarse sin depender del instructor

**Objetivo**

Entrar, encontrar trabajo y consultar el alcance correcto.

**Duración estimada**

8 minutos.

**Qué debe saber antes**

C0 aprobado; cuenta Admin individual y entorno autorizado.

**QUÉ HACER**

Deja que entre. Recorre los grupos del menú sin abrir todas las pantallas. Pide localizar Sedes, Notificaciones y Mi perfil; consulta General y una sede en Dashboard. No crear sedes por practicar orientación.

**QUÉ DECIR**

“Antes de actuar, revisa quién eres y qué sede estás mirando. Una notificación leída no significa que resolviste lo que avisa. Dashboard orienta; el detalle explica cada operación.”

**QUÉ MOSTRAR**

**Email**, **Contraseña**, **Entrar al CRM**; Dashboard: **General**, sede, **Comparar**, **Actualizar**, por cobrar y stock crítico; **Administración → Sedes**; **Notificaciones → No leídas / Todas → Marcar como leída**; **Mi perfil**, **Guardar perfil**, cambio de contraseña y **Salir**. Señala Menú en pantalla pequeña.

**QUÉ DEBE HACER EL APRENDIZ**

Entrar, cambiar alcance, interpretar un saldo y una alerta, localizar las tres pantallas y marcar una notificación ficticia. Identificar cómo cambiar clave sin revelar ni cambiar la real durante la demo.

**RESULTADO ESPERADO**

Reconoce su contexto, abre módulos desde menú y no interpreta la lectura como resolución.

**ERRORES QUE DEBES EXPLICAR**

Cuenta inactiva, contraseña incorrecta, filtro de sede y falta de permiso; cerrar pestaña no equivale a Salir. Sede nueva no crea stock y no se desactiva con empleados activos asignados.

**PREGUNTAS DE CONTROL**

1. ¿Dónde compruebas si la cifra es General o de una sede?
2. ¿Leer una alerta cancela o completa una operación?

**APROBADO SI**

Navega sin enlaces escritos a mano, explica alcance y localiza salida. Detalle: [Manual §4–6](user-manual.md#acceso), [§29](user-manual.md#notificaciones), [§31](user-manual.md#perfil).

### A2. Preparar un catálogo que el comprador pueda entender

**Objetivo**

Crear una ficha coherente, gestionar tres fotos, elegir versión y publicar sin confundir stock.

**Duración estimada**

13 minutos; campos complejos y creación independiente de listas se refuerzan posteriormente.

**Qué debe saber antes**

C0 y A1; categoría/listas preparadas, fotos propias y precio didáctico.

**QUÉ HACER**

Muestra dónde nacen categorías y marcas; utiliza las existentes. Haz juntos [E1](training-scenarios.md#e1). Abre un servicio preparado para distinguirlo de producto. No inventes datos de compatibilidad para ahorrar tiempo.

**QUÉ DECIR**

“La ficha explica qué vendemos; después registramos cuántas unidades hay. Una foto principal representa el artículo, pero reordenar la galería no cambia automáticamente esa elección. La variante es una versión, no una sede. La mano de obra es un servicio, no stock.”

**QUÉ MOSTRAR**

**Categorías**: campos de Producto/Variante y filtros; **Marcas y vehículos**: marcas de artículos, modelos/generaciones/OEM; **Inventario → Crear producto**, Información, Detalles, Compatibilidad, Precio y Variantes; **Agregar imágenes**, **Hacer principal**, flechas, **Quitar**; **Guardar y asignar inventario**. **Catálogo publicado → Editar producto e imágenes / Configurar publicación → Guardar publicación**. Servicio/categoría activos y **Guardar servicio / Guardar categoría**.

**QUÉ DEBE HACER EL APRENDIZ**

Preparar ficha ficticia y versiones, cargar tres fotos, cambiar principal/orden, guardar y comprobar que editar nombre conserva fotos. Publicar con foto y explicar qué bloque configuraría si cambian datos por variante.

**RESULTADO ESPERADO**

Ficha guardada y galería con una principal; publicación válida, sin asumir que hay stock. Terminar entradas y comprobación pública en A3.

**ERRORES QUE DEBES EXPLICAR**

Publicar sin imagen; archivo mayor de 5 MB/formato inválido; SKU repetido; campos obligatorios; servicio activo bajo categoría inactiva. Compatibilidad general no tiene años/OEM editables: esas opciones avanzadas aparecen en compatibilidad propia de variante. Principal de variante y principal de imagen son diferentes.

**PREGUNTAS DE CONTROL**

1. ¿Qué debes verificar antes de publicar?
2. ¿Dónde registras stock de una versión en BOG?
3. ¿Qué pasa con los servicios si su categoría está inactiva?

**APROBADO SI**

Guarda y reconoce publicación/foto/variante sin inventar stock; conserva las fotos al editar. Si sólo observó variantes o listas, sus competencias quedan pendientes. Detalle: [Manual §7–9](user-manual.md#productos), [§19](user-manual.md#servicios).

### A3. Abastecer y trasladar con trazabilidad

**Objetivo**

Diferenciar entrada, salida, saldo final, mínimo y traslado; verificar origen y destino.

**Duración estimada**

11 minutos, con formulario de producto ya guardado.

**Qué debe saber antes**

A2; unidades ficticias contadas, ambas sedes activas, permisos de cada etapa.

**QUÉ HACER**

Completa las entradas de E1. Ejecuta [E2](training-scenarios.md#e2) dejando al aprendiz narrar saldos antes de confirmar. Explica Salida/Ajuste sobre un ejemplo distinto y reserva el [taller de movimientos](training-scenarios.md#movimientos) para su práctica independiente; no “corrijas” la transferencia con ellos.

**QUÉ DECIR**

“Este formulario dice Ajustar existencias, pero agrega una entrada. En Movimiento, Ajuste a cantidad final fija el saldo. Pedir el traslado no reserva unidades; al despachar salen de BAQ y sólo al recibir entran en BOG.”

**QUÉ MOSTRAR**

**Existencias → Sede → Producto o SKU → Buscar**, **Solo stock bajo**, **Mínimo → Guardar mínimo**; **Movimiento**: Entrada/Salida/Ajuste a cantidad final, Cantidad/Nueva existencia y Motivo, **Registrar movimiento**; **Movimientos**; **Transferencias → Nueva transferencia → Agregar → Solicitar transferencia → Ver detalle → Despachar → Confirmar recepción**. Cancelación sólo de Solicitada, con motivo.

**QUÉ DEBE HACER EL APRENDIZ**

Registrar entradas por sede y variante; configurar un mínimo sin cambiar stock; trasladar dos unidades BAQ → BOG y comprobar saldos y movimientos. Resolver verbalmente un conteo físico y una salida insuficiente.

**RESULTADO ESPERADO**

En E2, variante Básica pasa de BAQ 6/BOG 1 a 4/3; en tránsito es 4/1. No duplica entrada en destino ni confunde mínimo con unidades.

**ERRORES QUE DEBES EXPLICAR**

Stock insuficiente al despachar aunque la solicitud se creó; salida excesiva; ajuste interpretado como suma; cancelación no disponible En tránsito/Recibida; recepción completa, no parcial. Movimientos muestra hasta 150 recientes: usar Reportes para periodos/exportación.

**PREGUNTAS DE CONTROL**

1. ¿Qué saldos hay mientras las dos unidades están En tránsito?
2. ¿Guardar mínimo suma unidades?
3. ¿Cómo retiras una solicitud aún no despachada?

**APROBADO SI**

Predice y comprueba las tres etapas con sus movimientos, sin ajustes ficticios. Detalle: [Manual §10–12](user-manual.md#inventario).

### A4. Reutilizar cliente y vehículo

**Objetivo**

Encontrar antes de crear y partir del cliente sin pedir nuevamente sus datos.

**Duración estimada**

7 minutos.

**Qué debe saber antes**

A1; datos ficticios y listas vehiculares disponibles.

**QUÉ HACER**

Inicia [E3](training-scenarios.md#e3), sólo cliente/vehículo. Pide buscar por contacto, corregir un dato y revisar historial; si no existe aún historial, explica ese vacío.

**QUÉ DECIR**

“Un cliente registrado es reutilizable. Ad hoc guarda contacto sólo en ese documento. Antes de cotizar, verifica cuál automóvil vamos a atender; tener cliente no garantiza tener el vehículo correcto.”

**QUÉ MOSTRAR**

**Clientes → Buscar cliente → Buscar → Nuevo cliente → Crear cliente**; **Editar → Guardar cambios**, Cliente activo; **Vehículos → Agregar vehículo → Marca/Modelo/Versión → Guardar vehículo**, **Ver compras**; **Nueva cotización / Nueva venta** desde el detalle.

**QUÉ DEBE HACER EL APRENDIZ**

Crear cliente ficticio sin duplicarlo, registrar vehículo con año válido, corregir una nota y abrir Nueva cotización con las selecciones verificadas.

**RESULTADO ESPERADO**

Cliente/vehículo vinculados; formulario comercial reutiliza la información. Un único vehículo activo puede quedar preseleccionado: lo comprueba.

**ERRORES QUE DEBES EXPLICAR**

Duplicar para cambiar teléfono; año incompatible con generación; desactivar interpretado como borrar historial; completar con placa/VIN inventados para un vehículo real.

**PREGUNTAS DE CONTROL**

1. ¿Cómo corriges contacto sin crear otro cliente?
2. ¿Qué revisas aunque el vehículo aparezca seleccionado?

**APROBADO SI**

Encuentra y reutiliza sus registros y distingue datos parciales de datos comprobados. Detalle: [Manual §13–14](user-manual.md#clientes).

### A5. Cotizar, editar, registrar envío y convertir

**Objetivo**

Conservar una única cadena comercial y reconocer cuándo se consume stock.

**Duración estimada**

10 minutos.

**Qué debe saber antes**

A3/A4; cliente/vehículo, sede y servicio elegibles, vigencia válida.

**QUÉ HACER**

Continúa E3. Anota stock antes de cotizar y después de convertir. Detén la explicación antes de confirmación para que el aprendiz diga qué cambiará y qué se conservará.

**QUÉ DECIR**

“Cotizar no reserva ni descuenta unidades. Marcar como enviada registra ese hecho, no manda automáticamente un mensaje. Convertir genera la venta confirmada usando sede, datos y precios de la propuesta; aquí sí se valida y consume stock.”

**QUÉ MOSTRAR**

**Nueva cotización**, Sede, cliente/vehículo, productos/servicios, Cantidad, Descuento COP, Válida hasta; **Crear cotización → Editar → Guardar cambios → Marcar como enviada → Convertir en venta → Confirmar → Ver en Órdenes**. Estados Borrador/Enviada/Convertida y opción de rechazo según estado.

**QUÉ DEBE HACER EL APRENDIZ**

Crear propuesta, editar una nota, marcar enviada y convertir una vez. Comparar cliente, vehículo, líneas, total y sede con la venta generada.

**RESULTADO ESPERADO**

Cotización Convertida, una venta Confirmada, stock descontado una vez y ningún pago inventado.

**ERRORES QUE DEBES EXPLICAR**

Vencida/terminal/ya convertida, stock cambiado, sede inactiva o servicio indisponible. Vigencia vacía usa configuración, no un plazo fijo. Admin puede tener edición de Enviada que el colaborador no tiene.

**PREGUNTAS DE CONTROL**

1. ¿En qué paso se descuentan unidades?
2. ¿Qué datos no tienes que volver a escribir?
3. ¿Debes crear otra venta si ya aparece Venta generada?

**APROBADO SI**

Completa la conversión única, verifica vínculo y explica el envío como estado. Detalle: [Manual §15](user-manual.md#cotizaciones), [§34](user-manual.md#flujo-comercial).

### A6. Venta directa, abono, saldo y terminación

**Objetivo**

Registrar dinero didáctico y terminación por separado, sin repetir la operación.

**Duración estimada**

8 minutos; pagos de E3 y ejemplo preparado de venta directa E4.

**Qué debe saber antes**

A5; entorno aislado sin dinero real y saldo de la venta comprobado.

**QUÉ HACER**

Completa E3 con abono/saldo y terminación. Muestra [E4](training-scenarios.md#e4) sin convertir de nuevo la propuesta; la práctica independiente de venta directa puede quedar en refuerzo.

**QUÉ DECIR**

“Pagada no significa Completada. Este pago registra dinero recibido; terminar indica que entregamos o atendimos. Si la respuesta del guardado es incierta, primero consultamos pagos y saldo, no repetimos el cobro.”

**QUÉ MOSTRAR**

**Órdenes → Nueva venta**, Sede/Vendedor opcional, líneas y **Registrar pago ahora**; **Registrar venta** crea Confirmada. Detalle: **Registrar pago**, Monto/Método/Referencia/Notas, saldo, **Marcar completada**. Cancelar cuando se ofrece no es devolución bancaria. Buscar/Estado/Pago/Origen y Ver orden.

**QUÉ DEBE HACER EL APRENDIZ**

En venta de $950.000, registrar $400.000, explicar saldo $550.000, registrar saldo didáctico y completar sólo la atención terminada. Señalar cómo inicia una venta sin cotización.

**RESULTADO ESPERADO**

Pago parcial → Pagada sin cambio automático a Completada; luego terminación explícita y saldo cero en E3.

**ERRORES QUE DEBES EXPLICAR**

Monto mayor al saldo, pago duplicado por repetir clic, vendedor de otra sede, cambio de sede que limpia líneas. Wompi como método de un registro interno no abre un cobro público; no borrar pagos históricos ni asumir devolución al cancelar venta.

**PREGUNTAS DE CONTROL**

1. ¿Cómo compruebas si quedó guardado un abono incierto?
2. ¿Una venta Completada puede tener saldo?
3. ¿En qué difiere la venta directa Admin de Crear venta pendiente del colaborador?

**APROBADO SI**

Registra abono y saldo correctos, explica ambos estados y evita una segunda venta. Para aprobar venta directa debe ejecutar E4 sin ayuda en sesión o refuerzo. Detalle: [Manual §16–17](user-manual.md#ventas).

### A7. Organizar y cerrar una atención en agenda

**Objetivo**

Programar con disponibilidad y distinguir atención completada, cancelación y no asistencia.

**Duración estimada**

7 minutos; citas alternativas de E5 preparadas para consulta.

**Qué debe saber antes**

Responsable con jornada, sin ausencias ni conflictos en la franja; servicio activo.

**QUÉ HACER**

Ejecuta la cita principal de [E5](training-scenarios.md#e5). Muestra alternativas separadas; nunca convierte una completada en Cancelada o No asistió. Consulta Calendario antes y después de reprogramar.

**QUÉ DECIR**

“La agenda depende de quién atiende y cuándo está disponible. Guardar vuelve a validar. No asistió no significa que completamos. El calendario consulta eventos; sus cambios se hacen en el módulo de origen.”

**QUÉ MOSTRAR**

**Citas → Nueva cita**, Responsable, cliente/contacto, Vehículo, Servicio, Estado inicial, Horario Colombia, **Crear cita → Confirmar → Reprogramar → Guardar cambios → Iniciar → Completar**. **No asistió**, **Cancelar cita** en registros distintos. Calendario: Semana/Agenda, fuentes y eventos.

**QUÉ DEBE HACER EL APRENDIZ**

Crear Solicitada, confirmar, reprogramar a franja libre, iniciar y completar; explicar las alternativas con registros separados.

**RESULTADO ESPERADO**

Cita/agenda coherentes; no genera una cita adicional para cambiar horario ni promete aviso automático al cliente.

**ERRORES QUE DEBES EXPLICAR**

Ausencia, solapamiento, fin anterior a inicio; la excepción fuera de jornada sólo si se ofrece y autoriza, nunca para saltar cualquier conflicto. Modificar horarios/ausencias no reprograma citas existentes automáticamente.

**PREGUNTAS DE CONTROL**

1. ¿Qué revisas si el responsable no está disponible?
2. ¿Qué estado corresponde si el cliente no vino?

**APROBADO SI**

Comprueba disponibilidad y estado final; para certificar cancelación/no asistencia debe practicar las ramas separadas. Detalle: [Manual §20–21](user-manual.md#citas).

### A8. Preparar el trabajo del equipo y entender comisiones

**Objetivo**

Relacionar persona, acceso, sede, jornada, ausencia, tarea, meta y comisión sin confundirlos.

**Duración estimada**

8 minutos de recorrido práctico con registros preparados; altas/ediciones independientes en refuerzo.

**Qué debe saber antes**

Cuenta Admin autorizada; empleado ficticio disponible; fechas separadas de E5.

**QUÉ HACER**

Sigue el [taller de personal](training-scenarios.md#personal). En la inicial, el aprendiz localiza contextos y modifica una tarea/meta ficticia; no crea siete formularios apresuradamente. Agenda refuerzo para altas no practicadas.

**QUÉ DECIR**

“Empleado y cuenta son diferentes. Dar acceso CRM no concede todas las funciones. Fecha límite no reserva agenda. El avance es el total nuevo, no lo que se suma. Ganada es una comisión de venta terminada, no dinero ya transferido al empleado.”

**QUÉ MOSTRAR**

**Empleados → Registrar empleado / Dar acceso CRM → Crear acceso CRM**, sede, Ver horario/ausencias/tareas; **Horarios → Guardar intervalo / Guardar excepción**; **Ausencias → Guardar ausencia** (Aprobada); **Tareas → Guardar tarea** y Programar en agenda; **Metas → Guardar meta / Avance → Registrar avance / Completar**; **Comisiones → Ver detalle**.

**QUÉ DEBE HACER EL APRENDIZ**

Localizar vínculo/sede/jornada, explicar una ausencia y una excepción; asignar/seguir una tarea preparada y cambiar avance de 2 a 4 escribiendo 4; identificar comisión de E3 si aplica.

**RESULTADO ESPERADO**

Identifica origen de disponibilidad, separación de accesos y avance manual; consulta el historial de comisión, sin intentar crearla o liquidarla.

**ERRORES QUE DEBES EXPLICAR**

Desactivar empleado no desactiva usuario; cambiarlo de sede puede rechazarse si conserva citas futuras activas o tareas programadas activas con fin futuro en la sede actual: revisar los compromisos, no borrar historial ni fingir terminación. Excepción de fecha sustituye jornada de ese día; ausencia se registra ya aprobada. Tarea programada debe tener rango válido del mismo día. Meta al 100 % no se cierra sola; Vencida no es Completada. Cancelaciones conservan historial según módulo.

**PREGUNTAS DE CONTROL**

1. ¿Cómo se cierra el acceso de una persona, además de desactivar empleado?
2. ¿Qué escribes para cambiar avance acumulado de 2 a 4?
3. ¿Ganada prueba que la comisión se pagó al empleado?

**APROBADO SI**

Explica las separaciones y demuestra las acciones asignadas; las otras altas se califican sólo al practicarlas. Detalle: [Manual §22–27](user-manual.md#empleados).

### A9. Revisar evidencia, reportes y configuración

**Objetivo**

Consultar/decidir con autorización y entender el alcance de los resultados.

**Duración estimada**

8 minutos.

**Qué debe saber antes**

Caso ficticio preparado o evidencia autorizada; permisos de conciliación, reportes y configuración.

**QUÉ HACER**

Realiza el [taller de control](training-scenarios.md#control). Enseña las ocho familias eligiendo una pregunta para cada una; practica filtro/exportación de una. No cambia configuración real ni inventa evidencia para cerrar un caso.

**QUÉ DECIR**

“Conciliar es investigar y dejar una decisión respaldada. No edita el dinero ni el stock. El reporte responde al alcance aplicado, no a lo que acabas de escribir sin aplicar. La vigencia configurada sirve a nuevas cotizaciones, no reescribe las anteriores.”

**QUÉ MOSTRAR**

**Conciliaciones de pagos → Ver caso → Iniciar revisión → Registrar decisión**, justificación/evidencia e historial; Escalar revisión deja abierto. **Reportes**: Ventas, Productos, Pagos, Cartera, Inventario, Movimientos, Cotizaciones, Clientes; **Aplicar filtros**, **Exportar Excel**. **Configuración → General / Ventas y cotizaciones / Usuarios**, **Vigencia predeterminada de cotizaciones**, Guardar cambios, roles Administrador/Usuario.

**QUÉ DEBE HACER EL APRENDIZ**

Identificar por qué falta evidencia y no resolver sin ella; elegir reporte para saldo y stock, aplicar sede/periodo y exportar. Localizar la vigencia y usuarios sin cambiar permisos ni claves. Decisión real sólo en caso ficticio autorizado.

**RESULTADO ESPERADO**

Lectura/decisión trazable según caso; reporte del alcance aplicado; configuración comprendida sin modificaciones accidentales.

**ERRORES QUE DEBES EXPLICAR**

Consulta no concede decisión. Escalar/devolución requerida no cierra; “requerida” no ejecuta reembolso. Fechas invertidas, filtros no aplicados y cambio de familia que conserva sede pero restablece otros filtros. Inventario no usa fechas; Pagos no descuenta reembolsos del resumen de completados. Usuarios no ofrece editor individual de capacidades comerciales.

**PREGUNTAS DE CONTROL**

1. ¿Resolver conciliación modifica el pago o inventario?
2. ¿Qué revisas al cambiar de reporte?
3. ¿Cambiar vigencia altera una cotización ya creada?

**APROBADO SI**

Selecciona alcance correcto, descarga sólo datos ficticios autorizados y explica qué no hace conciliación. Sin caso ejecutable, registrar decisión queda No visto. Detalle: [Manual §18](user-manual.md#conciliaciones), [§28–30](user-manual.md#reportes).

## 6. Itinerario colaborador: sólo su espacio

### C1. Reconocer su jornada y alcance

**Objetivo**

Encontrar trabajo propio y conocer límites sin abrir módulos Admin.

**Duración estimada**

3 minutos, después de C0.

**Qué debe saber antes**

Cuenta Usuario individual, empleado activo/sede y permisos preparados.

**QUÉ HACER**

Entrar con el aprendiz; pedir identidad/sede y siguiente prioridad. Abrir calendario y resumen permitido, no Dashboard administrativo.

**QUÉ DECIR**

“El sistema ya sabe quién eres, a qué sede perteneces y qué información puedes manejar. No eliges otra sede para vender, no abres ventas ajenas ni Configuración Admin. Si falta una función, pedimos revisar la autorización, no usamos la cuenta de otra persona.”

**QUÉ MOSTRAR**

**Inicio → Lo siguiente en tu día**, Resumen comercial, **Ver calendario / Ver tareas**; **Mi calendario → Semana / Agenda**; **Resumen del negocio → Desde / Hasta → Aplicar**, contexto de sede y desempeño. Agregados operativos no son ingresos/costos globales ni acceso al detalle ajeno.

**QUÉ DEBE HACER EL APRENDIZ**

Identificar su próxima cita/tarea, abrirla desde navegación y explicar a quién pedir ayuda si falta sede o permiso.

**RESULTADO ESPERADO**

Reconoce prioridades y datos propios; no intenta ampliar acceso modificando enlaces.

**ERRORES QUE DEBES EXPLICAR**

Sin vínculo/sede, filtros de fecha/fuentes y bloques sin permiso; vacío no siempre es error.

**PREGUNTAS DE CONTROL**

1. ¿Puedes escoger otra sede si tu sede no tiene stock?
2. ¿Ver actividad de compañía te permite abrir ventas de otro colaborador?

**APROBADO SI**

Localiza trabajo e identifica límites. Detalle: [Manual §32.1–32.2](user-manual.md#colaborador).

### C2. Cotización propia y venta única

**Objetivo**

Completar operación propia autorizada sin repetir datos ni pagos.

**Duración estimada**

10 minutos.

**Qué debe saber antes**

C0/C1; consulta, creación, edición, envío, conversión y acciones de ventas autorizadas; stock de su sede.

**QUÉ HACER**

Ejecuta la parte comercial de [E6](training-scenarios.md#e6). Muestra una venta pendiente preparada para contrastar el alta directa, sin crear una segunda venta para la misma cotización.

**QUÉ DECIR**

“Enviar congela la edición propia de esta propuesta. Convertir ya genera una venta confirmada; continúa esa misma. Una venta directa propia empieza Pendiente y consume stock al confirmar, no al crearla. Registrar pago y completar son permisos y acciones diferentes.”

**QUÉ MOSTRAR**

**Mis cotizaciones → Nueva cotización**, cliente registrado/vehículo, cantidades, descuento, vigencia; **Crear cotización → Editar → Guardar cambios → Enviar cotización → Convertir en venta** con confirmaciones. **Mis ventas → Ver venta → Registrar pago / Completar venta**; alta directa **Crear venta pendiente → Confirmar venta** sólo como alternativa distinta.

**QUÉ DEBE HACER EL APRENDIZ**

Crear/editar borrador propio, enviar, convertir una vez; localizar venta generada, registrar dinero didáctico si tiene permiso y completar la atención simulada. Explicar comisión aplicable sin asegurar que toda venta la genera.

**RESULTADO ESPERADO**

Documentos propios vinculados, sede derivada y estados separados. Si una capacidad falta, se documenta la limitación y se deriva al autorizado.

**ERRORES QUE DEBES EXPLICAR**

Editar Enviada como si fuera Borrador, stock insuficiente, monto excesivo o resultado incierto. No hay cancelación administrativa ni gestión del módulo Clientes en su espacio.

**PREGUNTAS DE CONTROL**

1. ¿Debes confirmar otra vez la venta generada por conversión?
2. ¿Qué haces si falta Registrar pago?
3. ¿Cuándo consume stock la venta directa propia?

**APROBADO SI**

Ejecuta las acciones concedidas, comprueba la cadena y solicita ayuda correctamente para las no concedidas. No se certifica una capacidad ausente. Detalle: [Manual §32.3–32.4](user-manual.md#colaborador).

### C3. Resolver tarea, medir meta y consultar comisión

**Objetivo**

Terminar trabajo y medir avance sin confundirlo con ventas automáticas o liquidación.

**Duración estimada**

5 minutos.

**Qué debe saber antes**

Tarea y meta propias activas, contexto comercial de E6.

**QUÉ HACER**

Deja completar la parte operativa de E6. Pregunta qué valor escribirá antes de guardar avance.

**QUÉ DECIR**

“Puedes ejecutar tu tarea, no reasignarla a otros. El avance de meta es manual y acumulado: para pasar de dos a cuatro escribes cuatro. Puedes crear una personal; no redefinir una asignada. Ganada no indica transferencia al empleado.”

**QUÉ MOSTRAR**

**Mis tareas → Ver detalle → Iniciar → Completar**; **Mis metas → Avance → Nuevo avance → Registrar avance**, **Crear meta personal → Guardar meta**, cierre manual; **Mis comisiones**, estados Pendiente/Ganada/Anulada y filtros.

**QUÉ DEBE HACER EL APRENDIZ**

Iniciar/completar tarea, actualizar meta acumulada, crear personal si se ofrece y explicar comisión de venta completada o ausencia legítima de ella.

**RESULTADO ESPERADO**

Tarea Completada y meta con avance correcto; consulta propia sin crear comisión manual.

**ERRORES QUE DEBES EXPLICAR**

Vencimiento no reserva agenda; ventas no avanzan automáticamente metas; llegar al objetivo no sustituye Completar; no cancelar asignada como personal.

**PREGUNTAS DE CONTROL**

1. ¿Qué escribes para pasar de avance 2 a 4?
2. ¿Puedes cambiar la definición de una meta asignada?
3. ¿Toda venta pagada genera comisión Ganada?

**APROBADO SI**

Demuestra tarea/avance y explica origen/estado de comisión; si crear personal sólo se mostró, marcar refuerzo. Detalle: [Manual §32.5](user-manual.md#colaborador).

### C4. Novedades, identidad y salida segura

**Objetivo**

Atender novedades y cerrar su sesión individual.

**Duración estimada**

2 minutos.

**Qué debe saber antes**

Cuenta propia y notificación ficticia.

**QUÉ HACER**

Pide abrir notificación, indicar trabajo pendiente y localizar datos/clave. La salida efectiva se realiza después del ejercicio final.

**QUÉ DECIR**

“Leída sólo habla de la notificación. Tu perfil no cambia sede ni permisos. Al terminar, salimos; no compartimos esta sesión para que otro trabaje.”

**QUÉ MOSTRAR**

**Notificaciones → No leídas → Marcar como leída**, **Mi perfil → Guardar perfil / Cambiar contraseña**, **Salir**.

**QUÉ DEBE HACER EL APRENDIZ**

Marcar una notificación, explicar cómo modificar datos/clave sin revelarlos y ubicar Salir.

**RESULTADO ESPERADO**

Identidad y lectura personal comprendidas, sin cambios de autorización.

**ERRORES QUE DEBES EXPLICAR**

Clave actual incorrecta/confirmación distinta; desactivar empleado y usuario son distintos; compartir credenciales no resuelve límites.

**PREGUNTAS DE CONTROL**

1. ¿Cambiar email te cambia de sede?
2. ¿Cerrar pestaña sustituye Salir?

**APROBADO SI**

Atiende novedad y cierra sesión al terminar. Detalle: [Manual §32.6](user-manual.md#colaborador).

## 7. Itinerario ecommerce: comprador, soporte o demostración

### P1. Descubrir y elegir sin dudas de versión

**Objetivo**

Encontrar un artículo, revisar compatibilidad y comprobar versión/precio/disponibilidad.

**Duración estimada**

5 minutos, después de orientación pública de dos minutos.

**Qué debe saber antes**

Entorno público de entrenamiento, producto preparado; no necesita cuenta CRM.

**QUÉ HACER**

Inicia [E7](training-scenarios.md#e7). Deja que el aprendiz encuentre la ficha usando navegación/búsqueda, no una dirección directa. Explica Contacto sin enviar WhatsApp.

**QUÉ DECIR**

“Compras como invitado. Revisa versión y compatibilidad antes de agregar; Desde no es el precio de todas las versiones. La disponibilidad de red no asegura que cualquier sede tenga todo.”

**QUÉ MOSTRAR**

Inicio: **Explorar artículos**, Tienda y Contacto; **Buscar**, Categoría/Marca producto/filtros de vehículo, stock/destacados, orden y Limpiar; detalle, miniaturas, **Versión**, cantidad y **Agregar al carrito**. Solicitar visita por WhatsApp prepara mensaje, no confirma cita.

**QUÉ DEBE HACER EL APRENDIZ**

Buscar, filtrar y limpiar una restricción, abrir ficha, cambiar foto, elegir versión disponible y agregar una unidad.

**RESULTADO ESPERADO**

Carrito con versión/precio correctos; no confunde explorar con comprar ni consulta con reserva.

**ERRORES QUE DEBES EXPLICAR**

Versión sin elegir/agotada, exceso de cantidad, filtros que ocultan resultados; fotos distintas no son variantes por sí solas. No prometer instalación incluida si no se indica.

**PREGUNTAS DE CONTROL**

1. ¿Qué revisas cuando la tarjeta dice Desde?
2. ¿Solicitar visita por WhatsApp confirma la cita automáticamente?

**APROBADO SI**

Encuentra y agrega versión correcta sin ayuda. Detalle: [Manual §36.1–36.2](user-manual.md#compra).

### P2. Preparar pedido y aplicar entrega

**Objetivo**

Entender recogida y envío antes de pagar el total final.

**Duración estimada**

7 minutos; una rama ejecutada por aprendiz, la otra sobre pedido didáctico separado/preparado.

**Qué debe saber antes**

P1, contacto/destino ficticios válidos y entorno sin comunicaciones reales.

**QUÉ HACER**

Revisar carrito y preparar una orden de E7. Practicar una modalidad; demostrar la otra sin crear pedidos duplicados por la misma transacción. Si faltan tarifas de entrenamiento, explicar límite y marcar envío No visto.

**QUÉ DECIR**

“Subtotal todavía no es el costo final. Preparar orden no cobra. En recogida aplicas una sede con todo el pedido. En envío guardas dirección, calculas y aplicas tarifa. Cambiar la dirección exige repetir esos pasos para el nuevo destino.”

**QUÉ MOSTRAR**

Carrito: cantidad/Quitar/Seguir comprando/**Continuar compra**. Checkout: modalidad, Nombre completo/Correo/Celular, **Preparar orden**. Recogida: **Recoger en esta sede**, Sede aplicada. Envío: quién recibe, dirección, **Guardar dirección → Calcular envío → Aplicar tarifa**, Resumen final/**Listo para pagar**.

**QUÉ DEBE HACER EL APRENDIZ**

Comprobar líneas/subtotal, preparar pedido, aplicar modalidad asignada y señalar qué falta si pago está bloqueado; explicar la otra modalidad con registro preparado.

**RESULTADO ESPERADO**

Entrega aplicada y total final comprendido. Sin dirección en recogida, sin tarifa presumida por seleccionar sólo una opción.

**ERRORES QUE DEBES EXPLICAR**

No hay una sede con todo el carrito, dirección sin guardar, tarifa sin aplicar, cargos incompletos; no inventar destino ni costos/plazos fijos. Vaciar carrito no cancela pedido preparado.

**PREGUNTAS DE CONTROL**

1. ¿Qué falta después de seleccionar una tarifa?
2. ¿Qué vuelves a hacer si cambia dirección?
3. ¿Cuándo puedes afirmar el total final?

**APROBADO SI**

Aplica su rama, identifica el total y explica la otra; ejecución independiente de ambas se registra por separado. Detalle: [Manual §36.3–36.6](user-manual.md#compra).

### P3. Pago, incertidumbre, rechazo y confirmación

**Objetivo**

Explicar el resultado y recuperar la misma orden sin riesgo de duplicar cobro.

**Duración estimada**

4 minutos.

**Qué debe saber antes**

P2; pago de pruebas explícitamente aprobado o evidencia didáctica autorizada de estados existentes.

**QUÉ HACER**

En entorno aprobado, continuar al pago de pruebas; en caso contrario detenerse antes. Mostrar pendientes/rechazados/aprobados preparados; no buscar forzar un fallo en proveedor real. No usar credenciales bancarias.

**QUÉ DECIR**

“Volver del pago no prueba aprobación. Pendiente o resultado incierto requiere consultar, no pagar de nuevo. Si el rechazo es explícito y aparece Intentar pago nuevamente, continuamos la misma orden. Pago confirmado tampoco significa entrega terminada.”

**QUÉ MOSTRAR**

**Continuar al pago**, Abriendo pago seguro; **Estamos confirmando tu pago**, **Consultar nuevamente**, **Pago rechazado**, **Intentar pago nuevamente**, **Pago confirmado → Ver mi orden**; número, líneas, total, entrega y **Contactar por WhatsApp** sin enviar la demo.

**QUÉ DEBE HACER EL APRENDIZ**

Elegir acción segura para pendiente, incierto, rechazado y aprobado; localizar número/total en confirmación; ejecutar pago únicamente si el entorno lo habilita sin fondos reales.

**RESULTADO ESPERADO**

Comprende cuándo esperar, consultar o reintentar la misma orden; no crea otra venta/pedido por incertidumbre.

**ERRORES QUE DEBES EXPLICAR**

Ausencia del botón de reintento no habilita recrear pedido; descuento bancario sin confirmación requiere soporte privado/número de orden; no compartir enlace privado ni códigos. No se promete proveedor real operativo por demostración local.

**PREGUNTAS DE CONTROL**

1. ¿Qué haces si se sigue confirmando el pago?
2. ¿Cómo reintentas un rechazo explícito si se permite?
3. ¿Pago confirmado significa entrega completada?

**APROBADO SI**

Responde y demuestra lectura de estados; pago/reintento ejecutados se aprueban sólo con práctica segura verificable. Detalle: [Manual §36.7–36.8](user-manual.md#compra).

## 8. Frases que deben quedar claras

- “Crear un producto no crea inventario.”
- “El inventario pertenece a una sede y a un artículo o variante concretos.”
- “Cotizar no reserva stock; convertir valida y genera una venta.”
- “No arreglamos un pago creando otra venta.”
- “Una orden pagada no necesariamente está terminada.”
- “Las transferencias se reciben; no se simulan con un ajuste.”
- “Principal de variante no es principal de imagen.”
- “Marcar enviada no garantiza que el mensaje llegó al cliente.”
- “El colaborador trabaja dentro de su propio alcance.”
- “Ganada no significa comisión pagada al empleado.”
- “Conciliar documenta evidencia; no cambia dinero ni stock arbitrariamente.”

## 9. Qué no debe hacer el instructor

No enseñes de memoria si cambió la pantalla: pausa y consulta el capítulo aprobado. No inventes un permiso/botón ni digas que todos los colaboradores tienen las mismas acciones. No abras módulos Admin en su recorrido como atajo. No uses producción, datos reales, cuentas compartidas ni medios reales de pago para practicar. No borres historial para dejar “limpio” el ejercicio. No ajustes unidades que requieren traslado ni repitas cobros porque tardan. No afirmes Pagada = Completada, comisión Ganada = liquidada, ausencia = solicitud del empleado o visita WhatsApp = cita confirmada. No certifiques acciones que sólo hiciste tú.

## 11. Evaluación y refuerzo

**Admin capacitado para operación básica:** sin instrucciones paso a paso, completa producto + fotos + stock, cliente + vehículo, cotización → venta, abono/saldo, transferencia y cita. Comprueba estados/saldos y explica sus consecuencias. Para autonomía completa de otros módulos, demuestra también las competencias asignadas del taller de personal/control; una presentación no basta.

**Colaborador capacitado para su puesto:** entra con su cuenta, identifica trabajo propio, realiza cotización/venta autorizadas, tarea/meta, consulta comisión si corresponde y explica límites. No se exige ejecutar permisos que no tiene: se registra el alcance y a quién deriva cada acción.

**Persona capacitada para ecommerce:** navega hasta checkout, verifica versión/total, explica y practica la modalidad asignada, reconoce qué falta para pagar y resuelve verbalmente pendiente/rechazo/reintento sin otra orden. Para certificar ejecución de ambas entregas o pago, deben practicarse en entorno seguro; si no se pudo, quedan pendientes, no aprobados ficticiamente.

En el cierre de cinco/dos minutos comprueba comprensión y agenda las pruebas independientes que no caben. Cada competencia se marca con evidencia en [training-checklist.md](training-checklist.md). Si comete un error crítico —doble operación, stock de sede equivocada, compartir acceso, inventar dinero o evidencia— detén esa operación, revisa resultado y refuerza antes de aprobar. No hay examen cronometrado obligatorio ni política laboral nueva.
